# Focused technical privacy/security audit (internal)

Status: **SOURCE REVIEWED / PRODUCTION TO VERIFY**. Reviewed 2026-09-20 against `src/server/**`, relevant `app/api/**`, `app/admin/**`, highscore consumers, browser storage and selected security tests. Findings below distinguish demonstrated code behavior from live-environment questions. This is not a claim that production has been penetration-tested.

| Finding and evidence | Risk | Minimal action/status |
| --- | --- | --- |
| Anonymous `GET /api/highscores` previously serialized internal `ScoreEntry` with `userId`, run ID, arbitrary `meta` and details unused by the page (`app/api/highscores/route.ts`, `src/server/highscoreRepo.ts`). | Unnecessary public account-linked fields and precise history. | **Fixed in source:** dedicated public projection, date only, validated display fields, targeted test. Public names remain account-linkable by design. |
| `DELETE /api/users?id=` previously removed `users` and sessions only (`src/server/userRepo.ts`, route). | Linked scores and events could remain after self-deletion. | **Fixed for records with `user_id`:** cascade and targeted test. **TO VERIFY:** legacy name-only scores, concurrent writes on multi-instance production, backup/log copies and restore replay. Do not claim complete live deletion yet. |
| `sessions.expires_at` has an ordinary numeric index and expired records were removed only when read (`src/server/db.ts`, `src/server/sessionRepo.ts`). | Stale authentication records can remain in storage. | **Infrastructure prepared:** bounded, idempotent cleanup job, safe manual dry-run, authenticated cron route and once-daily `vercel.json` entry. Production dashboard evidence confirms a Production-only `CRON_SECRET`. **TO VERIFY:** deployment, live registration and execution; no production job is enabled. |
| Raw `activity_events` had no age-based pruning; admin overview/detail read all rows (`src/server/activityRepo.ts`, `src/server/adminAnalyticsRepo.ts`). | Granular learner history accumulates. | **Infrastructure prepared:** admin event metrics use a rolling 90-day window; the authenticated cron reuses the bounded cleanup and creates no derived learner rollup. **TO VERIFY:** final legal retention approval and deployed live job. |
| Admin audit writes apparent IP, actor/target IDs, action and timestamp to `console.info`; multiple server errors log error objects (`src/server/authSecurity.ts`, relevant routes). | Platform logs may hold account-linked data beyond an approved period. | Production evidence confirms Vercel Runtime Logs are active. Official Vercel documentation states Hobby Runtime Logs retain one hour; Vercel build logs are documented as stored indefinitely per deployment. **TO VERIFY:** dashboard access, deployment-retention policy, provider operational/audit-log and Observability retention, capture and redaction before notice wording. |
| Auth and route rate-limit buckets are process-local (`src/server/authSecurity.ts`, `src/server/routeRateLimit.ts`). | Multi-instance deployment may weaken limits and scatter short-lived IP/account keys. | **TO VERIFY:** live instance topology, forwarded-header trust and platform protections; fix only if demonstrated. |
| Session cookie is `HttpOnly`, `SameSite=Lax`, path `/`, and `Secure` in production mode; new login replaces the caller's old session (`src/server/sessionAuth.ts`, login/current routes). | Runtime HTTPS/domain settings and cookie forwarding are not proven by source. | **TO VERIFY** in live deployment; preserve existing expiry and session behavior. |
| Admin analytics APIs call `requireAdminApi`; `/admin` layout checks role. `GET /api/users` is admin-only; progress update checks target user/admin; current-user API serializes `UserProfile`, not password verifier fields. | Authorization and field exposure remain sensitive to regressions. | Existing targeted tests cover selected cases; rerun after API changes and verify deployed behavior. |
| Mutation routes use `enforceSameOriginMutation` based on Origin/Fetch Metadata and forwarded host/protocol (`src/server/requestOriginPolicy.ts`). | Proxy header trust model depends on the live deployment. | **TO VERIFY** provider forwarding/overwrite rules and cross-site behavior; source tests alone cannot establish production control. |
| Scoped source search found localStorage preferences but no service-worker registration, IndexedDB, external product analytics SDK, or external auth/email/AI/payment SDK. | Deployment can inject scripts/services or keep platform logs absent from source. | Vercel Web Analytics is enabled; Speed Insights is not enabled; Vercel Integrations has no installed integrations. **TO VERIFY** live scripts, analytics fields/configuration and network egress beyond these verified facts. |
