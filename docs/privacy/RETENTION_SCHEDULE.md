# Retention and deletion schedule (internal)

Status: **PROVISIONAL / TO VERIFY**. Source reviewed 2026-09-20; production and operator evidence updated 2026-09-21. Red Island Studio provisionally selected 90 days for raw activity events and account-lifetime retention for profiles and highscores until deletion, with no derived per-learner event history after raw events expire. These are implementation inputs, not a legally approved 90-day storage claim. Rationale/legal review, production controls, holds and review date remain **TO VERIFY**.

Any maintenance job must be idempotent, bounded, and observable without logging secrets or broad learner exports. Do not claim 90-day enforcement until the live cron is deployed, authenticated, observed and legally approved. No production job or database migration has been run or enabled by this document.

Repository implementation: `src/server/privacyRetention.ts` processes at most 10,000 records per collection per run in 500-record batches. `scripts/run-privacy-retention.ts` remains a manual dry-run by default, refuses missing `MONGODB_URI`, and requires an explicit approval environment flag for execution. `GET /api/cron/privacy-retention` reuses the same operation and accepts only `Authorization: Bearer <CRON_SECRET>` when a non-empty server-side `CRON_SECRET` is configured. It returns aggregate counts and cutoffs, not learner records. `vercel.json` schedules it once daily at `0 18 * * *` (18:00 UTC; Hobby timing may vary within the hour). Vercel registers cron jobs only on a production deployment, and no such deployment has occurred. The admin event metrics read only the rolling 90-day window even before old rows are physically pruned; legal approval and verified live execution remain necessary for actual retention enforcement.

Production dashboard evidence confirms that a `CRON_SECRET` is configured as a Production-only Vercel Secret. Keep that scope and do not place its value in source, documentation, logs or responses. After an authorized deployment, verify the registered path/schedule, a successful aggregate-only run, retained in-window records, and failure visibility without exporting learner-identifiable rows.
